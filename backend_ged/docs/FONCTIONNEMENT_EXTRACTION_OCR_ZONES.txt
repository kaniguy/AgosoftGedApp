1. VUE D'ENSEMBLE
-----------------

L'extraction automatique des champs documentaires combine :

  • Des ZONES DE CAPTURE configurées par type de document (style Dokmee Capture)
  • Un moteur OCR PaddleOCR (PDF scannés / images)
  • Une extraction PDF native (texte sélectionnable, sans OCR)
  • Un repli par LIBELLÉ uniquement pour les champs sans zone
  • Un ajustement temporaire des zones côté écran de rattachement

Le fichier importé par l'utilisateur est TOUJOURS la source d'extraction.
Le « document modèle » (paramétrage) sert uniquement à POSITIONNER les zones
lors de la configuration ; il n'est pas relu lors de l'extraction au rattachement.


2. MODÈLE DE DONNÉES (PARAMÉTRAGE)
----------------------------------

Fichiers principaux :
  • parametrage/models/champs_document.py
  • parametrage/capture_storage.py
  • Migration 0008_capture_zones.py

TypeDocument
  • fichier_modele      : PDF/image de référence pour l'éditeur de zones
  • modele_page_count   : nombre de pages du modèle

ChampsDocument (par type de document)
  • ordre               : ordre d'affichage dans le formulaire (entier, unique par type)
  • capture_page        : index de page 0-based (0 = 1ère page)
  • zone_x, zone_y      : coin supérieur gauche de la zone (0.0 à 1.0)
  • zone_width          : largeur normalisée (0.0 à 1.0)
  • zone_height         : hauteur normalisée (0.0 à 1.0)
  • type_champ          : texte, nombre, date, etc.
  • libelle_champ       : libellé affiché et utilisé pour le repli libellé

Coordonnées NORMALISÉES (0–1) :
  • Indépendantes de la résolution du document importé
  • (0,0) = coin supérieur gauche de la page
  • Une zone à x=0.1, y=0.2, width=0.3, height=0.05 couvre 10 % depuis la gauche,
    20 % depuis le haut, sur 30 % de largeur et 5 % de hauteur de la page

Propriété has_capture_zone :
  • Vraie si zone_x, zone_y, zone_width, zone_height sont renseignés et > 0


3. CONFIGURATION DES ZONES (FRONTEND PARAMÉTRAGE)
-------------------------------------------------

Écran : /parametrage/champs_document/[typeDocumentId]/zones

Fichiers :
  • src/components/parametrage/capture/CaptureZoneEditor.jsx
  • src/services/captureZones.service.js
  • src/utils/captureZoneUtils.js

API :
  • POST/DELETE .../types-document/{id}/modele-capture/  → upload/suppression modèle
  • GET/PUT    .../types-document/{id}/capture-zones/    → lecture/sauvegarde zones

L'éditeur convertit pixels ↔ coordonnées normalisées via react-rnd.
Les zones sauvegardées en base s'appliquent ensuite à tout document importé
du même type (même mise en page relative attendue).


4. ÉCRAN DE RATTACHEMENT (FRONTEND)
-----------------------------------

Route : /gestion_documentaire/plan_geographique/[id]/rattacher

Fichiers :
  • src/components/gestion_documentaire/documents/DocumentRattachementPanel.jsx
  • src/components/gestion_documentaire/documents/DocumentPreview.jsx
  • src/components/gestion_documentaire/documents/CaptureZonesOverlay.jsx
  • src/components/gestion_documentaire/documents/CaptureZonesAdjustOverlay.jsx
  • src/services/ocr.service.js

Parcours utilisateur (actuel) :
  1. Choisir le type de document
  2. Importer le fichier (PDF ou image) → aperçu immédiat, SANS extraction auto
  3. Vérifier / ajuster les zones (« Ajuster les zones » sur l'aperçu)
  4. Saisir manuellement OU cliquer « Extraire les champs »
  5. Enregistrer le document

Ajustement local des zones (rattachement uniquement) :
  • zoneOverrides en mémoire (non sauvegardés en paramétrage)
  • Envoyés à l'API via le champ multipart zone_overrides (JSON)
  • Permet de corriger un léger décalage pour CE document sans modifier le modèle

Progression affichée pendant l'extraction :
  • 0–28 %  : envoi du fichier (XHR upload)
  • 28–94 % : traitement serveur (estimation)
  • 100 %   : réponse reçue


5. API D'EXTRACTION
-------------------

Endpoint :
  POST /api/gestion-documentaire/documents/extract-fields/

Corps (multipart/form-data) :
  • fichier         : document importé (obligatoire)
  • type_document   : ID du type (obligatoire)
  • zone_overrides  : JSON optionnel [{ champ_id, capture_page, zone_x, zone_y,
                      zone_width, zone_height }, ...]

Fichier vue :
  • gestion_documentaire/views/document_view.py → action extract_fields

Réponse JSON :
  • champs[]          : { champ_id, valeur, confidence, methode }
  • methode           : zones | zones+libelle | pdf_native | ocr | ...
  • zones_configurees : nombre de champs avec zone
  • compatibilite     : null ou { score, message, ... } si document incompatible
  • texte_complet     : texte OCR global (cache ou extraction complète)
  • ocr_disponible    : booléen


6. ORDRE D'EXTRACTION DES CHAMPS
--------------------------------

6.1 Ordre en base (champ « ordre »)
-----------------------------------
Les champs sont chargés avec :
  ChampsDocument.objects.filter(...).order_by("ordre")

Cet ordre définit :
  • L'affichage dans le formulaire de rattachement
  • L'ordre de parcours des champs lors du regroupement par page

6.2 Regroupement par page
-------------------------
Dans zone_extractor.py, les champs avec zone sont groupés ainsi :

  zones_by_page[capture_page].append(champ)

En parcourant la liste triée par « ordre », les pages sont traitées dans
l'ordre de PREMIÈRE APPARITION d'un champ sur cette page.

Exemple :
  ordre 1 → page 0
  ordre 2 → page 0
  ordre 3 → page 2
  ordre 4 → page 0

Ordre de traitement des pages : 0, puis 2 (page 1 ignorée si aucune zone).

6.3 Ordre au sein d'une page
----------------------------
Pour chaque page, les champs sont traités dans l'ordre où ils ont été ajoutés
au groupe, donc selon le champ « ordre » croissant parmi les champs de cette page.

6.4 Phases d'extraction (par page, pour chaque champ avec zone)
---------------------------------------------------------------
Pour chaque champ, dans l'ordre ci-dessus :

  PHASE A — PDF natif (si fichier PDF textuel)
    Méthode : pdf_native_zone
    Confiance : 1.0
    Extraction via PyMuPDF get_textbox() dans le rectangle de la zone

  PHASE B — OCR page entière (1 seul appel PaddleOCR par page)
    Méthode : ocr_zone_page
    • Toutes les lignes détectées sur la page sont mises en cache
    • Pour chaque champ restant : filtrage des lignes intersectant la zone
    • Assemblage du texte selon le type de champ (assemble_crop_text)

  PHASE C — OCR sur crop isolé (repli par champ en échec)
    Méthode : ocr_zone_crop
    • Découpe de la zone sur l'image
    • Nouvel appel PaddleOCR sur le crop uniquement
    • 2 marges testées (normale puis élargie), meilleur score conservé

6.5 Après les zones : repli libellé
-----------------------------------
Uniquement pour les champs SANS zone configurée (champs_sans_zones).

Les champs AVEC zone qui ont échoué ne passent PAS en repli libellé
(évite de remplir des valeurs fantaisistes sur un mauvais document).

6.6 Ordre dans la réponse API
-----------------------------
Le tableau « champs » de la réponse concatène :
  1. Résultats zone_results (ordre de traitement décrit ci-dessus)
  2. Puis résultats label_results (champs sans zone, ordre « ordre » en base)

Le frontend applique les valeurs sans dépendre de cet ordre (indexation par champ_id).


7. PIPELINE DÉTAILLÉ — EXTRACTION PAR ZONES
-------------------------------------------

Fichier : gestion_documentaire/services/zone_extractor.py

Étapes globales :
  1. Lecture des octets du fichier importé (_read_file_bytes, seek(0) après lecture)
  2. Filtrage des champs possédant une zone valide
  3. Application éventuelle des zone_overrides (zone_override.py)
  4. Boucle par page puis par champ (phases A, B, C)
  5. Construction du cache OCR (build_ocr_result_from_page_cache) pour repli libellé

Seuil de confiance minimum :
  OCR_MIN_ZONE_CONFIDENCE = 0.32 (ocr_service.py)
  En dessous : valeur ignorée pour ce champ

Formatage final :
  field_extractor._format_value_for_type()
  • date     → YYYY-MM-DD
  • nombre   → parsing montant
  • select   → correspondance avec options


8. MOTEUR OCR (PADDLEOCR)
-------------------------

Fichier : gestion_documentaire/services/ocr_service.py

Moteur :
  • PaddleOCR 3.x, singleton au démarrage (_get_ocr_engine)
  • Modèles : PP-OCRv5_mobile_det + latin_PP-OCRv5_mobile_rec
  • Préchargement optionnel au runserver (gestion_documentaire/apps.py)

Paramètres performance (valeurs dans ocr_service.py) :
  OCR_PDF_ZOOM           : zoom rendu PDF (ex. 1.2)
  OCR_MAX_IMAGE_SIDE     : redimensionnement max (ex. 1400 px)
  OCR_DET_LIMIT_SIDE_LEN : limite côté détection PaddleOCR (ex. 960)
  OCR_MAX_PAGES_NATIVE   : pages max extraction PDF native (ex. 50)
  OCR_MAX_PAGES_OCR      : pages max OCR image pour mode libellé (ex. 10)

Formats supportés :
  • PDF (.pdf)
  • Images : jpg, jpeg, png, webp, gif, bmp, tiff

PDF textuel (non scanné) :
  • extract_native_text_in_normalized_rect : texte dans une zone
  • _try_extract_pdf_native_text : texte page entière pour repli libellé
  • Pas d'appel PaddleOCR si le PDF contient assez de texte natif

OCR page entière (run_ocr_on_pil_image) :
  1. Rendu page PIL (render_page_as_pil) ou chargement image
  2. Redimensionnement (_resize_for_ocr)
  3. predict() PaddleOCR
  4. Parsing lignes avec positions normalisées (_parse_ocr_result_detailed)
     Chaque ligne : { text, confidence, cx, cy, bbox }

Affectation ligne → zone (filter_ocr_lines_in_rect) :
  • Intersection bbox OCR / rectangle de zone (ou centre dans la zone)
  • Marge normalisée ZONE_CROP_MARGIN / ZONE_CROP_RETRY_MARGIN


9. POST-TRAITEMENT DU TEXTE (zone_text_refine.py)
------------------------------------------------

Fichier : gestion_documentaire/services/zone_text_refine.py

assemble_crop_text(lines, champ) :
  • Adresses / texte long : toutes les lignes OCR de la zone, jointes
  • Montants / codes courts : une seule rangée horizontale dominante

refine_raw_for_champ(raw, champ) :
  • Adresses : lignes conservées, virgules pour champs « texte »
  • Dates : motif JJ/MM/AAAA ou JJ-MM-AAAA
  • Montants : _best_amount_token (gère « 4 731 », « 1.234,56 », etc.)
  • Facture n° : motif type FR-001
  • Commande n° : motif type 123/4567

score_zone_extraction :
  • Compare les tentatives OCR (marge normale vs élargie, crop)
  • Favorise les montants plus élevés pour éviter un chiffre parasite (« 4 » vs « 174.00 »)


10. REPLI PAR LIBELLÉ (field_extractor.py)
------------------------------------------

Fichier : gestion_documentaire/services/field_extractor.py

Utilisé seulement pour champs_sans_zones.

Stratégie _extract_raw_value :
  1. Chercher « Libellé : valeur » sur une ligne
  2. Libellé sur une ligne, valeur sur la suivante
  3. Recherche globale dans le texte complet

Correspondance stricte du libellé (pas de similarité floue).

Réutilise le cache OCR des pages déjà traitées (ocr_page_cache) si disponible,
sinon extract_text_from_file() sur le document importé.


11. DÉTECTION DOCUMENT INCOMPATIBLE
-----------------------------------

Dans extract_fields (document_view.py) :

Si des zones sont configurées :
  ratio = zones_remplies / zones_configurees
  Si ratio < 0.35 → compatibilite.message renvoyé au frontend

Signification : le document importé ne correspond probablement pas au modèle
(mauvais type, mise en page différente, scan illisible).


12. SURCHARGE DES ZONES (RATTACHEMENT)
--------------------------------------

Fichier : gestion_documentaire/services/zone_override.py

Le frontend envoie zone_overrides après ajustement manuel sur l'aperçu.
ZoneOverrideChamp encapsule un ChampsDocument avec coordonnées temporaires.
L'extraction utilise ces coordonnées à la place de celles en base.
Aucune écriture en base : ajustement local à la session de rattachement.


13. AFFICHAGE DES ZONES (APERÇU)
--------------------------------

CaptureZonesOverlay :
  • Mode lecture : rectangles colorés, sans libellé au-dessus
  • Vert = champ détecté (filledChampIds)

CaptureZonesAdjustOverlay :
  • Mode édition (react-rnd) : déplacement / redimensionnement
  • Conversion pixels ↔ normalisé via captureZoneUtils.js

Largeur de référence aperçu : CAPTURE_BASE_PAGE_WIDTH = 720 px
